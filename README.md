# OI 赛场：局域网 + LemonLime 自动测评

这不是“上传后再人工整理”的网盘。学生直接选择“考号紧接姓名”文件夹后，服务器会：

1. 从管理员上传的 LemonLime `.cdf` 读取题目名和 `subFolderCheck`；
2. 检查所选文件夹是否严格使用“考号紧接姓名”命名；
3. 检查每道题是否存在正确路径的源码，并拒绝路径穿越、可执行文件和重复源码；
4. 格式正确才调用 `lemon-headless`（直接链接 LemonLime core）测评；格式错误则保留提交并记 0 分；
5. 保存每题结果、总分和时间，按“总分降序、总时间升序”排名。

## 必须先知道的限制

官方 LemonLime 0.3.6.2 的 `lemon.exe` 没有批量测评 CLI；它只有 GUI。项目中的 `lemon-worker/main.cpp` 是一个很薄的无界面入口，调用的仍是 LemonLime 自己的 `Contest::judgeAll()`。因此需要用 Qt 开发包编译一次 worker，不能把 GUI 程序伪装成服务端接口。

更重要：LemonLime 在 Windows 上运行学生程序时不是强沙箱。正式比赛应把本系统放在专门的、可还原的 Windows 测评机/虚拟机，断开互联网，不要在存有个人文件的日用电脑上运行未知学生代码。

## 1. 环境

- Windows 10/11；
- Node.js 22.5 或更高（项目使用 Node 内置 SQLite）；
- `g++` 在 PATH 中；
- Qt 6.8+ 的 MinGW 开发包、CMake、Ninja，用于编译 Lemon worker。

当前 worker 明确只开放 C++（`.cpp/.cc/.cxx`），默认使用 `-std=c++14 -O2`。Python、Pascal、通信题和交互题需要分别增加编译器/运行器配置后再开放，不能只改网页允许的后缀。

## 2. 编译 Lemon worker

在 Qt 安装器中安装 Qt 6.8+ 的 MinGW 64-bit 套件。下载并解压本项目后，在资源管理器中打开解压得到的 `oi-lan-lemon` 文件夹，点击地址栏、输入 `powershell` 并回车。假设 Qt 的 CMake 前缀为 `C:\Qt\6.9.3\mingw_64`，在打开的 PowerShell 中执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-worker.ps1 `
  -QtPrefix C:\Qt\6.9.3\mingw_64 `
  -CompilerDir C:\Qt\Tools\mingw1310_64\bin
```

脚本会浅克隆官方 LemonLime 源码、加入本项目的 headless 入口，只构建 `lemon-headless.exe`，输出到 `bin/`。

## 3. 启动局域网网站

继续在该项目文件夹的 PowerShell 窗口中执行：

```powershell
npm install
npm start
```

也可以双击 `start.bat`；停止时双击 `stop.bat`。服务器默认监听 `0.0.0.0:3000`。教师本机访问 `http://localhost:3000`；学生访问 `http://教师电脑局域网IP:3000`。第一次启动会生成管理员令牌，显示在终端并写入 `data/admin-token.txt`。

Windows 防火墙若询问是否允许 Node.js 访问专用网络，选择“允许专用网络”，不要开放公用网络。

## 4. 管理员准备比赛

先用 LemonLime GUI 正常新建并配置比赛：

- 设置测试数据、分值、时间和内存；
- 题目的“源文件名称”决定学生源码文件名；
- “在子文件夹寻找”决定是否要求 `题目名/题目名.cpp`；
- 编译器配置名使用 `g++ / default`；
- 比赛目录必须含唯一 `.cdf` 和 `data/`。

然后把整个 Lemon 比赛目录压缩成 ZIP。登录网站管理员端：

1. 新建比赛并设置开始/截止时间；
2. 上传“公开题目包”（学生下载的题面、样例等）；
3. 上传“Lemon 比赛包 ZIP”（含 CDF 和私有数据）；
4. 导入 TXT/CSV 学生姓名（每行一个姓名或 CSV 第一列）；系统随机生成 `OI` 加 6 位数字的考号和 8 位个人提交码；
5. 先下载仅含姓名和考号的比赛名单，再下载含个人提交码的提交凭证并分别发给学生。
6. 如需提前收卷，在比赛管理卡片点击“立即关闭比赛”；关闭后停止新提交，但保留测评结果和排名。
7. 已关闭或已结束的比赛可以在网页中永久删除；删除前必须输入比赛名称确认，删除后无法恢复。

私有 Lemon 比赛包永远没有学生下载接口。

## 5. 学生提交格式

假设考号 `S001`、姓名 `张三`，CDF 中有 `sum`、`tree` 两题。学生在电脑上建立并直接选择以下文件夹，无需压缩：

```text
S001张三/
├─ sum.cpp
└─ tree.cpp
```

如果 Lemon 里 `tree` 勾选了“在子文件夹寻找”，则必须是：

```text
S001张三/tree/tree.cpp
```

服务器时间是唯一截止依据。截止后上传接口直接拒绝；每名学生默认只能提交一次，管理员可重置提交权限。

比赛结束后学生可以重复提交文件夹进行自主测评。管理员端“赛后补题情况”显示每名学生最近一次补题的状态、各题分数、总分和测试点详情；补题不修改正式成绩与排名。

## 6. DeepSeek 全员赛后复盘

比赛结束或由管理员关闭、且测评队列清空后，可在管理员比赛卡片输入 DeepSeek API Key，调用 1M 上下文的 `deepseek-v4-pro` 逐名分析最新提交。系统把每名学生的分析合并到：

```text
data/reviews/比赛编号/all-students-review.md
```

网页可直接下载该 Markdown 文档。系统会提取 ZIP 中的 Markdown、文本和 PDF 题面；扫描版 PDF 没有文字层时仍需另行提供文本题面。API Key 只保存在单次后台任务的内存中，不写入数据库或文件。姓名不会发送给 DeepSeek，但题目资料、考号、学生源代码、分数和测试点结果会发送到 DeepSeek；使用前应确认符合学校的数据与隐私要求。报告是模型生成的辅助材料，教练必须结合原始代码复核。

## 7. 数据与备份

所有持久数据在 `data/`：SQLite、题目包、私有数据和历次提交都在其中。比赛前后直接备份整个 `data/` 即可。不要把该目录提交到 Git，也不要把网站端口映射到互联网。

## 8. Windows 屏幕监考客户端

学生在每场比赛页面输入考号和个人提交码，验证通过后下载只属于本人的 `考号-监考登录器.exe`。登录器会自动填写当前网站 URL、比赛编号、考号和提交码，URL 输入框仍可修改；专属 EXE 内含个人提交码，禁止转发。客户端每 3 秒发送在线心跳和可见进程名称；服务器只在内存中保留最后一张图，约 12 秒无心跳显示离线。正常情况下每 30 秒截图一次；发现 QQ、微信、普通浏览器、远程控制或终端程序时立即截图并提醒学生，违规程序持续存在时每隔 30 秒重复截图上报，但不关闭程序、不锁屏。

客户端允许 `Code`、`devcpp`、`notepad`、Windows 桌面组件，以及由客户端以 `--app=考场地址` 启动的受控 Edge。不要直接从桌面打开 Edge。它不记录键盘、不录音、不录像、不写开机启动项；退出客户端后即停止上报。

学生尚无任何提交记录时，客户端关闭按钮会被拦截；提交成功（包括格式错误记 0 分）并等到下一次心跳后，客户端允许正常退出。普通用户态 EXE 无法防止断电、重启或管理员权限强制结束进程；需要强制约束时应另配 Windows 受限账户、AppLocker 或 Kiosk 策略。

重新生成 EXE：

```bat
cd proctor-client
build.bat
```

当前 EXE 没有商业代码签名证书，其他电脑首次运行可能出现 Windows SmartScreen 提示。正式使用前必须在备用电脑完整演练，并准备管理员令牌和任务管理恢复方案。单靠进程白名单不是强安全边界；更可靠的断网比赛仍应使用独立 VLAN/防火墙，只放行监考服务器地址。

## 配置项

```text
PORT=3000                 监听端口
HOST=0.0.0.0              监听地址
ADMIN_TOKEN=...           固定管理员令牌（不设置则自动生成）
LEMON_WORKER=...          自定义 lemon-headless 路径
CXX=...                   g++ 路径或命令名
MAX_STUDENT_ZIP_MB=20     学生提交文件夹总体积上限（保留旧变量名）
MAX_PACKAGE_ZIP_MB=512    比赛包上限
DATA_DIR=...              数据库与上传文件目录（默认项目内 data/）
```
